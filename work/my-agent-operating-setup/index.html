Why I built it

Agents are fast but forgetful and overconfident. I wanted them to behave like teammates who follow written rules, leave proper handoffs and prove their work before calling it done.

How it works

Shared rules. One global rule file applies to every project. It routes work by difficulty (small models for mechanical tasks, mid-size models for normal work, the largest models for architecture and high-risk changes), and each task announces which tier it uses and why. I audited my agent definitions against this table and moved several to a better-fitting tier.

Required habits. Default skills make every agent debug systematically, verify before reporting a task as complete, and brainstorm and stress-test plans before building.

Shared memory. Every project has a control-center note in my Obsidian vault with a section written for the next agent, the commands that are verified to work, the current status, durable decisions and the next step. Agents update it when they finish a task, so a new session, or a different agent, can pick up the work without me repeating myself.

Clear boundaries. When two agents work on related things, the notes say who owns what. In Money Printer, Claude and Codex run separate tracks and never share credentials or publishing state.

Knowledge library. A library folder collects what I have studied with AI help, including small retrieval corpora that agents can query. The retrieval part is still in progress.

Token hygiene. A command-line proxy filters long shell output before it reaches the agent, which keeps sessions cheaper and more focused.

Honest limits

  • This setup is tuned for one person. It has not been tested with a team.
  • I use AI to write a lot of my code, so some parts I understand at the level of design and behaviour rather than every line. Learning those internals properly is one of my goals.

What I took away

Most agent failures I see are not about intelligence. They come from missing context, unclear ownership or nobody checking the result. Writing those things down fixes more problems than switching models.
